THE PROBLEM

          
“Container exited” is not the same as “workload succeeded.”

        

        

          
Seven scheduled OCR jobs appeared as completed in the deployment history. Their public result logs showed three successful comparisons and four failures.

          
The collector checks the operation status and benchmark output before recording a successful result. The artifact runner separately compares downloaded bytes with a locally computed hash.

LIVE EVIDENCE

          
What has actually run on Nosana.

          
Generated from the evidence files in the repository. Each job links to its public explorer record; open Results for the actual output and exit status. OCR history includes one manual success and seven scheduled attempts: three successes and four failures. Scores measure word overlap with each PDF’s text layer, a small proxy for OCR quality. They do not measure reading order, tables, equations or customer demand.

          
Historical OCR logs were recovered from the public explorer on 18 Nov 2026. Runtime-reported hardware is retained because current node metadata can differ from historical logs; the cause of the difference is unresolved. A dashboard label of completed is not sufficient evidence of a successful benchmark.

            Current integration boundary
            
Retrieval works today through an HTTP endpoint served by the job itself. The Nosana CLI’s own artifact output flag is not implemented in version 1.0.133 (see docs/nosana-cli-findings.md). We have not confirmed that this endpoint is the mechanism Nosana recommends. The record above is a simulation rehearsal and can never pass the live gate.
